Standard for audio preservation and restoration – Technical metadata for describing the processing and handling of audio objects

Introduction

This standard sets out the vocabulary to be used in describing the processing and handling of audio objects in audio preservation work. This metadata, sometimes referred to as ‘process history’ or ‘digi-prov’, describes the details of how audio objects are treated and/or migrated. Essentially it provides the ‘who’, ‘where’, ‘what’ and ‘how’ information that clarifies the provenance of the audio object with regard to the work that has been done to restore and/or preserve the object. This vocabulary takes the form of an Extensible Markup Language (XML) schema. By doing so it provides a structured human readable instance document that can be easily parsed and manipulated using any of a number of freely available programming libraries and tools.

1 Scope

This standard concerns the technical documentation of the processing and handling of audio files and physical audio formats carried out during audio preservation and restoration work. This documentation, referred to as metadata from here on, provides a description of where the work occurred, who did the work, when the work was completed, and how the work was done, including a full description of the audio signal chain as it was configured during the processing.

4.4.1.3.1.8 syncGroup

The syncGroup element shall be used to define a group of adl, audioObject and or audioFileReference objects. This group shall be defined by the following characteristics:

All streams/tracks that are referenced by a patch from a device element’s media channel in the device chain will be understood to have been played or processes processed synchronously according to their respective time-code positions on a virtual time-line.

The virtual time-line is implied from the single object designated by the masterMediaRef attribute.

The duration of the playback/processing may be limited using the timeRange sub-element of the syncGroup.

Multiple sync-groups may be used to indicate parallel processing of input and output media attached to the media channels of devices in the device chain. Both the input and output media must reside in the same syncGroup.

4.4.1.3.1.9.1.1.1.7.1.4.1 group
