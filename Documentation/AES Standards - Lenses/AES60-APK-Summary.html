1. Executive Overview

This document synthesizes the AES60 Core Audio Metadata standard and its broader ecosystem of AES technical metadata standards (including AES31, AES41, AES-X098C, iXML, and AES-X230), establishing an architectural mapping for the Sampler.Like.Audio (APK) software sampler engine and sample library structure.

By harmonizing classic hardware sampler workflows (such as pad banks, choke/mute groups, keygroup program chromamapping, velocity switching, and zero-crossing chop points) with formal standards-compliant audio object schemas, Sampler.Like.Audio ensures lossless session transfer, non-destructive editing provenance, and archival integrity across modern production ecosystems.

2. Core Metadata Standards Matrix

AES60-2011 & EBU Tech 3293

Core Audio Metadata framework defining Dublin Core based metadata elements for broadcast and studio audio objects (title, creator, format, channel assignment, rights).

AES31 (Parts 1 - 4)

Digital audio file interchange, FAT32 disk formatting, Broadcast Wave Format (BWF), Simple Project Exchange (ADL), and XML-based Audio Decision Lists.

AES41 (Parts 1 - 5)

In-band embedded metadata within PCM audio sample LSBs for recoding decision data, MPEG Layer II, AAC, Dolby E, and EBU loudness/true-peak parameters.

AES-X098C & iXML

Administrative & structural processing history for audio objects (signal graph, hardware chain, DSP transformations), combined with location recording track/take metadata.

3. Sampler.Like.Audio (APK) Architecture & AES Metadata Mapping

The Sampler.Like.Audio (APK) engine structures digital sample playback, pad performance, and sample library management into standardized metadata nodes:

Pad & Voice Engine Mapping

  • Pad & Program Objects (APK 404 - 484): Each pad kit (e.g., Kick, Snare, Closed Hat, Open Hat, Toms) is assigned an AES60 audioTrack and channelIndex, maintaining explicit track function metadata.
  • Velocity Layering (Up to 4 Layers per Pad): Multi-velocity sample layers are mapped to AES60 technical metadata parameters, enabling dynamic response curves.
  • Mute / Choke Groups: Explicit note-off routing triggers defined in AES31 ADL event decision structures to handle real-time voice choking (e.g., Open Hi-Hat cut by Closed Hi-Hat).
  • Non-Destructive Slice Points: Chop mode slices (start, end, loop, zero-crossing points) are recorded as AES31 XML ADL region events without modifying underlying .wav sample files.

Preservation & Processing History (AES-X098C)

Every audio processing action performed inside the editor (bit-crushing, 12-bit decimation, analog filter modeling, ADSR envelopes, pitch-shifting) is tracked as a processEvent within an AES-X098C compliant XML signal graph record.
